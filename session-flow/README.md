# session-flow

Claude Code 세션에서 시킨 일과 그 흐름을 한 줄씩 보여 주는 모드입니다.

```
❯ 세션 진행 흐름을 보는 로그 모드 만들기          21:02
  · 스킬 sundry, plugin-authoring
  · 조사 claude-code.d.ts, reference.md 외 3개
  · 수정 register.tsx, flow-log.ts 외 3개
  · 에이전트 ✓ 표시 형식 평가 37초 · sonnet
  · 검색 claude code mods pane scroll
  · 커밋 세션 흐름 모드 추가
✓ 13분 · session-flow 모드 완성, 테스트 통과
```

## 쓰는 법

`/flow`를 치면 창이 열리고, 다시 치면 닫힙니다. 일이 돌고 있는 중에도 바로 동작합니다.

창을 열어 둔 폴더는 기억해서, 다음에 그 폴더에서 세션을 시작하면 자동으로 열립니다. `/flow`나 `✕`로 닫으면 다음부터 안 열립니다. `/flow`를 쓴 적 없는 폴더에서는 열리지 않습니다. 자동으로 여는 건 창이 옆에 붙는 fullscreen에서만이고, 터미널 폭이 110칸 이상이어야 합니다. 폭이 모자라면 넓힐 때 뜨고, 그 전에 `/flow`를 치면 바로 열립니다.

fullscreen 터미널에서는 채팅 옆에 붙고, 그 밖에는 프롬프트 위에 열립니다. 로그가 창보다 길어지면 최신 줄을 따라갑니다. `ctrl+x tab`으로 창에 초점을 옮긴 뒤 화살표로 올려 볼 수 있고, 올려 둔 동안에는 화면이 끌려 내려가지 않습니다. `End`로 맨 아래로 내려오면 다시 따라갑니다. `Esc`를 누르면 프롬프트로 돌아갑니다.

창 폭이 좁으면 문장 전체가 보이도록 필요한 만큼 여러 줄로 접힙니다.

## 남기는 것

| 표시 | 뜻 |
|---|---|
| `❯` | 시킨 일. 줄 끝에 시각이 붙습니다 |
| `스킬`, `검색`, `웹 읽기`, `수정`, `질문`, `워크플로`, `게시` | 한 일 |
| `조사` | 파일 읽기와 `grep`, `cat` 같은 읽기 전용 명령. 고치는 도중의 읽기는 따로 남기지 않습니다 |
| `에이전트` | `⋯` 실행 중(백그라운드 작업 대기 포함), `✓` 끝남, `✗` 실패, `?` 끝을 확인하지 못함(세션을 다시 열었거나 엔진 목록에서 사라진 경우). 시간은 기다린 시간까지 포함합니다 |
| `커밋`, `푸시`, `PR` | 명령 중 예외로 남기는 결과 |
| MCP 서버 이름 | MCP 도구 호출 |
| `✓`, `⋯`, `■`, `✗` | 요청의 끝. 차례로 완료, 그 요청에서 띄운 에이전트가 도는 중, 중단, 오류 |
| `?` | Claude가 답을 기다리는 질문. 답을 기다리는 동안 노란색, 그 뒤로는 흐리게 표시합니다 |

같은 종류가 이어지면 한 줄로 합칩니다. 일반 명령, 실패한 호출, 서브에이전트 안의 도구 호출, `/config` 같은 로컬 명령은 남기지 않습니다.

## 답을 기다리는 질문

Claude가 답변에서 묻거나 결정을 요청하면 프롬프트 바로 위 띠에 고정합니다. 다른 일이 지나가도 밀려나지 않고, `/flow` 창을 닫아 둬도 보입니다.

```
? 모든 세션에 설치할지 결정 필요                                  [ 확인 ]
```

다음 요청을 보내거나 `확인`을 누르면 띠에서 내려가고, 로그에는 `?` 줄로 계속 남습니다. `확인`은 클릭하거나 `ctrl+x tab` 뒤 `Enter`로 누릅니다. 질문 찾기는 한 줄 요약과 같은 Haiku 호출에서 함께 하며, 모델을 쓰지 않을 때는 물음표로 끝나는 마지막 문장을 씁니다. 그래서 물음표 없이 요청한 말은 놓칠 수 있습니다.

## 보관

세션마다 최근 500줄을 보관하고, 전체 6,000줄까지 저장합니다. 넘치면 오래된 세션의 로그부터 밀려납니다. `--resume`, `--continue`, 세션 안 `/resume`으로 다시 열면 살아나고, `/branch`는 원래 로그를 이어받고, `/clear`하면 새로 시작합니다. 저장은 턴이 끝날 때 합니다.

`claude -p` 같은 자동 실행은 저장하지 않고 요약도 호출하지 않습니다.

## 알려진 한계

- `context: fork`로 도는 스킬은 요청 줄이 남지 않습니다. 엔진이 그 실행의 요청 이벤트를 내지 않습니다.
- 턴 도중에 친 글은 친 시점에 기록합니다. 그래서 앞선 턴의 끝 줄보다 위에 오거나, 큐에서 취소해도 로그에 남을 수 있습니다.

## 설정

`/config`의 플러그인 항목에서 바꿉니다.

| 설정 | 기본값 | 내용 |
|---|---|---|
| `palette` | `catppuccin` | `catppuccin`, `dracula`, `tokyo-night`, `rose-pine`, `nord`, `gruvbox`, `kanagawa`는 같은 이름의 테마에 맞춘 고정 색입니다. 다크 배경 기준이라 라이트 테마에서는 `claude`를 고르세요. `claude`는 Claude Code 테마를 따라갑니다. 창 배경은 창을 다시 열면 바뀝니다 |
| `showNarration` | 켜짐 | 도구 사이에 모델이 한 말의 첫 문장도 남깁니다 |
| `summarize` | 켜짐 | 80자 이상인 요청과 40자 이상인 최종 답을 Haiku로 한 줄로 줄이고, 답에서 질문을 찾습니다. 턴마다 최대 두 번 모델을 호출하며 세션 자격 증명으로 과금됩니다. 호출이 실패하면 잘린 원문이 남습니다 |

## 개발

```bash
claude plugin validate session-flow
claude plugin test session-flow
```

창 스크롤(최신 줄 따라가기)은 테스트 키트가 다루지 않습니다. 실제 터미널에서 확인합니다.
